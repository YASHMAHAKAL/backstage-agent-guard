# Cloud platform chart inputs and local checks

Argo CD installation is owned by the [Terraform Argo Helm root](../aws/argocd/README.md).
Its operator settings live inline with that release. The separate
[Terraform Argo bootstrap root](../aws/argo-bootstrap/README.md) owns the two
bootstrap namespaces, AppProjects, Applications, private GitOps connection,
and a fixed-response ALB bootstrap Ingress.
No generated bootstrap YAML or manual `kubectl apply` step is required.

The remaining `values/` files configure the AWS Load Balancer Controller and
External Secrets Operator. Terraform passes these values to Argo Applications;
Argo installs and reconciles the pinned public charts. Terraform never owns
those two Helm releases. AWS Pod Identity and limited Secrets Manager access
remain in the EKS foundation root. External Secrets watches only
`rizz-staging` and uses its controller Pod Identity.

The actual Rizz.AI `SecretStore`, `ExternalSecret`, Deployments, Services and
Ingress are generated by the [Backstage cloud recipe](../../plugins/agent-guard-backend/src/cloudSnapshot.ts)
as a single frozen nine-file GitOps change. A reviewed Backstage proposal opens
the PR; after human merge, the automatic Rizz.AI Argo Application syncs it.
The secret _values_ are privately stored in AWS Secrets Manager and never enter
the GitOps PR or Terraform state. The first cloud path does not exist in the
GitOps repository yet, so Argo can only deploy it after that first merge.
The bootstrap Ingress creates an operator-IP-restricted HTTP 503 ALB so its
DNS name is known before importing the demo HTTPS certificate; it does not
serve Rizz.AI.

## Local verification

```sh
node --test infra/cloud-platform/charts.test.mjs
terraform -chdir=infra/aws/argocd test -no-color
terraform -chdir=infra/aws/argo-bootstrap test -no-color
```

The Node test checks the pinned chart metadata and controller values. If
`RIZZ_CHART_TEST_DIRECTORY` points to locally downloaded public controller
archives named `<chart>-<version>.tgz`, it also verifies their SHA-256 digests
and renders them with Helm. These tests do not contact AWS or Kubernetes. The
Argo installer uses the separate checksum-verifying
`fetch-argocd-chart.mjs` for its pinned archive.

The observer RBAC recipe under `observer/` remains a separate, restricted
operator setup. It does not give the app publisher EKS credentials.

## Live order and cleanup

For an authorized future demo, apply and verify the EKS foundation first,
then the Argo Helm root, then the Argo bootstrap root. The latter waits for
the two platform controller Applications to be Synced and Healthy and creates
the fixed-response ALB. Verify live Pod Identity, webhook and CRD readiness,
then import the ALB-hostname certificate privately before an app release.
The first Backstage release PR creates the app manifests. Its human merge
triggers Argo reconciliation; check actual Pods, HTTPS, secret sync and image
digests before claiming success.

Remove the app Ingress, then the bootstrap Ingress and confirm ALB deletion
while the controller still runs. Then remove the remaining Argo bootstrap
objects, Argo Helm release, and EKS
foundation in that order under reviewed teardown plans. Retained registry and
state are separate decisions. The $5 budget and four-hour checkpoint remain
constraints, not authorization to create AWS resources.
